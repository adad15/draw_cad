# 错误码、日志与排查

## 1. 日志机制

`WorkflowMessageLog` 负责 warning/error 输出：

| 场景 | 日志路径 |
|---|---|
| 单独命令 | `D:\vs2022 code\auto_cad\warnings_errors.txt` |
| 批量工作流 | `{output_dir}\warnings_errors.txt`，默认 `batch_output\warnings_errors.txt` |

日志格式：

```text
[WARNING] Row 62 group A:B has a non-numeric length and was skipped: 人行横洞
[ERROR] Failed to resolve board length workbook for sheet ...
```

`WorkflowMessageLog` 会写入 UTF-8 BOM，便于 Windows 工具直接打开。

## 3. 常见 warning

| warning | 含义 | 是否阻断 |
|---|---|---|
| `non-numeric length` | 板长表包含人行横洞、车行横洞等非普通板长行 | 否 |
| `slab number but no length` | 有板号但缺少长度 | 否，该行跳过 |
| `length not found` | 某病害板号在板长 JSON 中不存在 | 否，使用默认 8m |
| OpenXLSX PDB warning | 第三方库缺少调试符号 | 否 |

## 4. 排查顺序

1. 先看命令行退出码。
2. 再看控制台输出的最后一个 `[ERROR]`。
3. 查看 `warnings_errors.txt`。
4. 对批量流程，确认是否卡在工作表识别、板长匹配、JSON 导出或 DXF 写出中的某一步。
5. 如果涉及中文路径，确认当前构建包含 `GetCommandLineW()` 参数解析修复。
